
# UI Rules

> This document defines the visual, interaction, layout, and experience rules for the Klick ONN Finvest & Air Travels platform.
>
> While `ui-tokens.md` defines design tokens such as colors and typography, this document explains how those tokens should be applied throughout the product.
>
> Every interface should follow these guidelines to ensure a consistent, premium, and professional experience.

---

# Design Philosophy

The website should communicate:

- Trust
- Professionalism
- Expertise
- Simplicity
- Premium Quality
- Reliability

The website represents a consultancy firm.

It should never feel like:

- A travel booking website
- An ecommerce platform
- A government portal
- A dashboard-first application
- A template copied from ThemeForest

Every screen should immediately communicate that visitors are interacting with professionals who provide consultation and guidance.

---

# User Experience Philosophy

Every page should answer three questions within the first few seconds.

Who are we?

↓

What do we do?

↓

What should the visitor do next?

If a page fails to answer these questions, redesign it.

---

# Visual Hierarchy

Hierarchy should always be established through:

Spacing

↓

Typography

↓

Contrast

↓

Color

Never rely on color alone.

Never rely on shadows alone.

Spacing is the primary design tool.

---

# White Space

White space is intentional.

Do not fill empty space simply because it exists.

Premium interfaces breathe.

Large sections should feel open and uncluttered.

---

# Layout Rules

Content should be aligned consistently.

Maintain predictable spacing between sections.

Avoid unnecessary nesting.

Keep layouts balanced.

Use asymmetrical layouts only when they improve storytelling.

---

# Section Structure

Every major page should follow a logical flow.

Hero

↓

Supporting Content

↓

Service Details

↓

Trust Building

↓

Call To Action

↓

Footer

Users should never feel lost while scrolling.

---

# Hero Sections

Every hero section should include:

- Clear headline
- Supporting description
- Primary CTA
- Secondary CTA (optional)
- Relevant imagery or illustration

Avoid overwhelming the hero with excessive text.

Avoid multiple competing calls to action.

---

# Buttons

Every page should have one primary action.

Primary buttons should visually dominate secondary actions.

Button labels should describe outcomes.

Good examples:

Book Consultation

Talk to an Expert

Contact Us

Request a Callback

Avoid vague labels like:

Click Here

Submit

Learn

Go

---

# Cards

Cards should communicate information clearly.

Cards should never exist purely for decoration.

Each card should have:

Purpose

Hierarchy

Padding

Consistent spacing

Hover feedback when interactive

Never overcrowd cards.

---

# Icons

Icons should support text.

Icons should never replace text.

Use icons consistently.

Avoid mixing icon styles.

---

# Images

Images should feel authentic.

Prioritize:

Professional offices

Business meetings

Financial consultation

Travel planning

Families

Business travellers

Avoid cliché stock photography whenever possible.

Do not overload pages with decorative images.

---

# Illustrations

Illustrations should support understanding.

Never compete with important content.

Maintain a consistent illustration style throughout the project.

---

# Animations

Animations should improve usability.

Good animation:

Explains hierarchy.

Provides feedback.

Improves navigation.

Creates delight.

Bad animation:

Distracts users.

Slows interaction.

Competes with content.

Every animation should have a purpose.

---

# Motion Rules

Prefer subtle transitions.

Avoid exaggerated movement.

Avoid bounce effects.

Avoid excessive parallax.

Respect reduced motion preferences.

Users should notice polish—not animation.

---

# Navigation

Navigation should remain simple.

Every page should be reachable within a few clicks.

Highlight the current page.

Primary CTA should remain visible.

Navigation should become sticky after scrolling.

---

# Forms

Forms should feel approachable.

Always display:

Labels

Validation

Errors

Success messages

Loading state

Required fields should be clearly marked.

Never rely on placeholder text as labels.

---

# Content Rules

Content should educate before selling.

Write naturally.

Avoid marketing buzzwords.

Avoid exaggerated promises.

Use short paragraphs.

Use descriptive headings.

Use bullet points when helpful.

Business language should remain professional and honest.

---

# Responsive Design

Design mobile-first.

Desktop should enhance the experience—not redefine it.

Every component should gracefully adapt to:

Mobile

Tablet

Laptop

Desktop

Large Displays

No feature should exist only on desktop.

---

# Accessibility

Accessibility is mandatory.

Ensure:

Keyboard navigation

Visible focus indicators

Semantic HTML

Proper heading structure

Descriptive alt text

Readable contrast ratios

Accessible forms

Accessibility should be considered during implementation—not after.

---

# Loading States

Never leave users waiting without feedback.

Every asynchronous action should include an appropriate loading state.

Skeleton loaders are preferred over spinners whenever practical.

---

# Empty States

Every empty state should:

Explain why it's empty.

Suggest the next action.

Maintain visual consistency.

Empty screens should never feel broken.

---

# Error States

Errors should:

Explain the issue.

Avoid technical jargon.

Offer recovery when possible.

Never expose internal implementation details.

---

# Calls To Action

Every important page should guide users toward meaningful actions.

Examples:

Call Now

WhatsApp

Book Consultation

Contact Us

Request a Callback

Avoid overwhelming users with too many equally important actions.

---

# Footer

The footer should reinforce trust.

Include:

Business information

Navigation

Services

Contact details

Legal links

Copyright

Avoid unnecessary clutter.

---

# Consistency

Consistency is more valuable than creativity.

If multiple solutions exist, choose the one that aligns with the existing design system.

Users should feel like every page belongs to the same product.

---

# Final Principle

Every design decision should make the website easier to understand, easier to use, and easier to trust.

If a UI element does not improve clarity, usability, accessibility, or trust, reconsider its necessity before implementation.
